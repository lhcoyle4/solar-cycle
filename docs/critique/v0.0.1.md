# Critique — v0.0.1

This is the bootstrap release: docs, tooling, and a minimal `core` +
`environment` render pipeline to prove the verification loop end-to-end.
**No builder/critic gauntlet has run yet** — there is no game content to
gauntlet. This report documents what was manually verified, not a critic
score.

## What was checked

Using `tools/verify/screenshot.mjs` against `npm run build && npm run
preview` (headless Chromium, 1920×1080):

| Check | Result |
|---|---|
| App loads, reaches `window.__SOLAR_READY__` | ✅ |
| Console errors (boot scene, noon) | 0 |
| Console errors (boot scene, evening) | 0 |
| Console errors (`environment` showcase mode, evening) | 0 |
| Draw calls (boot scene: sky dome + ground plane) | 2 (well under the 1500 budget) |
| fps (headless, software-rendered WebGL — advisory only, see note) | ~4-5 |
| Day/night cycle changes sun elevation, sky color, ground exposure | ✅ (see screenshots) |
| Module isolation (unit-tested: a throwing `init`/`update` disables only that module) | ✅ |

**fps note**: this cloud environment renders WebGL in software
(`GL_CLOSE_PATH_NV` / "GPU stall due to ReadPixels" warnings confirm no
hardware acceleration). 4-5 fps here says nothing about real performance;
it is not evaluated against the ≥50 fps budget until measured on real
hardware. Draw calls and zero console errors are the hard gates at this
stage, and both pass.

## Honest assessment

This is **not** AAA and is **not** claiming a critic score. It is a
working procedural sky/sun/ground pipeline (Preetham analytic sky model +
a directional sun light + a deterministic procedural ground texture, all
CC0/code — no image assets) that:

- Renders without programmer-art flat primitives-only geometry (the sky is
  a physically parameterized model, not a solid-color background).
- Responds correctly to time-of-day.
- Produces zero console errors and a trivial draw-call count.
- Is visually flat and unconvincing as "AAA" — no atmospheric depth
  beyond basic fog, no bloom/sun-glare shaping beyond the shader's own
  glow term, no ground detail beyond tiled procedural noise, no visible
  clouds, no horizon haze gradient tuning. This is expected: it exists to
  prove the render/verification pipeline works, not to pass a module
  gauntlet.

## Ranked issues for the first real builder wave

1. **Sky tuning** (`environment`): turbidity/rayleigh/mie values are
   rough guesses; need iteration against real reference lighting (golden
   hour warmth, midday blue saturation, night starfield) once a critic
   round runs.
2. **No horizon detail**: nothing breaks up the flat ground-meets-sky
   line — no distant terrain silhouette, no atmospheric haze layer.
3. **Ground material is a placeholder**: deterministic noise texture
   only, no real PBR normal/roughness maps, no macro-scale variation —
   this is explicitly a placeholder, not a `terrain`/`materials` module
   deliverable.
4. **No scene composition beyond one plane**: no props, no characters, no
   town — none of this exists yet; it's the very next waves' job.
